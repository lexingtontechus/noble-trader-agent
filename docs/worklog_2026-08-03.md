# Worklog: Noble Trader Plugin Architecture Refactor

## Date: 2026-08-03

## Goal
Consolidate plugin deployment into `desktop-plugins/` only, remove legacy `plugins/` directory,
re-architect the setup/onboarding flow where the plugin is integrated into the Hermes runtime
via `watchdog.sh`, and establish clean separation between user-facing plugin and backend.

## Issues Found

### 1. STDOUT Pollution in `agent_api_shim.py`
**Root cause:** The agent's `structlog` configuration (`hermes.core.logging`) writes log lines
to `sys.stdout` during `create_app()` / `load_config()`. The shim's `logging.disable(CRITICAL)`
only suppresses Python's stdlib logging module, NOT structlog. This left ~33 log lines on stdout
before the final `print(json.dumps(...))` line.

`plugin_api.py` reads stdout with `proc.stdout.strip().splitlines()[-1]` — which DID get the
JSON, but the pipe could deadlock if stdout filled the OS buffer (64KB) before the process
finished, causing the "Timed out connecting to Hermes backend after 15000ms" error.

**Fix:** Use `io.StringIO()` + `contextlib.redirect_stdout()` to capture ALL stdout during the
TestClient run. After the run, drain the captured buffer to STDERR, then emit a single JSON
line to the real stdout. Result: exactly 1 line on stdout, 0 structlog noise.

### 2. Missing `/api/plugin/health` Route
**Root cause:** The shim maps `op="health"` → `/api/plugin/health`, but `app.py` only had
`/health` and `/health-simple` (not under the `/api/plugin/` namespace). This caused 404s
when `plugin_api.py` called `_call_agent_shim("health")`.

**Fix:** Added `@app.get("/api/plugin/health")` route that mirrors `/health-simple` output
with `local_plugin: True` flag.

### 3. Legacy `NOBLE_TRADER_REDIS_URL` References
**Root cause:** The old env var name `NOBLE_TRADER_REDIS_URL` (along with `NOBLE_TRADER_REDIS_CHANNEL`,
`NOBLE_TRADER_REDIS_CONSUMER_GROUP`) was still referenced in backend code. The canonical name
is now `NOBLE_TRADER_PROXY_REDIS_URL`.

**Fix:** Removed the `os.getenv("NOBLE_TRADER_REDIS_URL")` fallback in `sse_consumer.py`
(lines 126-129). Updated `app.py:1053` error message and `sse_consumer.py` docstrings to
reference `NOBLE_TRADER_PROXY_REDIS_URL` exclusively.

### 4. Stale `.env.local` Field Names
**Finding:** The user's `.env.local` has legacy keys: `NOBLE_TRADER_REDIS_URL`,
`NOBLE_TRADER_REDIS_CHANNEL`, `NOBLE_TRADER_REDIS_CONSUMER_GROUP`, `METAAPI_DEMO=true`,
`NOBLE_TRADER_PROXY_REDIS_URL` (without creds, wrong scheme). The backend now expects
`NOBLE_TRADER_PROXY_REDIS_URL` (full URL with embedded creds), `NT_MODE`, and dual-mode
MetaApi keys (`_DEMO`/`_LIVE` pairs).

**Status:** NOT auto-fixed (user secret file). The setup wizard collects the correct fields
and POSTs to `/setup`, which rewrites `.env` with the correct key names. User needs to re-run
setup to migrate. (Not a code bug — this is expected onboarding flow.)

## Architecture (Post-Refactor)

```
User opens Noble Trader plugin in Hermes desktop app
  ↓
Plugin's useAgent() → ctx.rest('/setup-status') → Hermes backend
  ↓
Hermes backend /api/plugins/noble-trader/health → _call_agent_shim() →
  Shells out to:  <runtime>/.venv/Scripts/python.exe scripts/agent_api_shim.py
  with:           PYTHONPATH=<runtime>/src
                  SECRETS_ENV_FILE_PATH=<runtime>/.env
                  cwd=<runtime>
  ↓
agent_api_shim.py → TestClient(app) → GET /api/plugin/health → JSON to stdout (1 line)
  ↓
plugin_api.py parses JSON → returns to plugin → Setup tab shows

Onboarding:
  User fills wizard (NOBLE_TRADER_PROXY_REDIS_URL, NOBLE_TRADER_QUOTE_PROXY_URL,
    TRADINGVIEW_API_KEY, METAAPI_*_DEMO/LIVE pairs, NT_MODE)
  → POST /setup → /api/plugins/noble-trader/setup → shim POST /setup
  → app.py:setup_submit() writes .env + config/user.local.yaml + migrates DuckDB
```

## Additional Findings

### Supabase Variables — Required
`SUPABASE_URL` and `SUPABASE_ANON_KEY` are **required** in `.env.local` and used for:
1. **`proxy_delivery_log` table** — `proxy_liveness.py` polls this Supabase table every 60s for proxy heartbeat (CRITICAL if no heartbeat in 480s). This is Monitor A-pipeline (signal pipeline health).
2. **`nt_sweep_result` + `nt_regime_log` tables** — `SupabaseBackfiller` backfills 365 days of historical sweep/regime data into DuckDB.

Both use the `SUPABASE_ANON_KEY` (RLS-protected publishable key), NOT the service-role key.

### MetaApi Token — Single Credential Per Account
**Confirmed correct:** The user's interpretation is accurate:
- A **single MetaApi admin token** is generated per MT4/MT5 account
- This same token authenticates both the trading REST endpoints AND MetaStats
- The MetaApi SDK (`account.get_account_information()`, `account.get_positions()`, `account.get_orders()`) makes RPC calls to the user's MT4 account
- MetaStats SDK reuses the same token internally
- Both the plugin and backend use the **same token** — it authenticates access to the user's specific MT4/MT5 account

### Portfolio Endpoint Enhancement
Added `get_orders()` to `MetaApiBroker` (maps to MetaApi REST `GET /users/current/accounts/:accountId/orders`) and included `orders` in the `/api/plugin/brokerage` JSON response alongside `equity`, `positions`, `open_trades`, and `trades`.
